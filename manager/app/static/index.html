AI 网关管理台

0new-api 连接（自用网关内核 + 面板）

首次使用：这里会替你初始化 new-api 的 root 管理员并登录。密码只保存在本机挂载卷里，不会上传任何地方。

1Codex 账号（可多个）

凭据在 ~/.codex/auth.json 的 tokens 里（先 codex login 登录过）。每行一个账号，会变成独立渠道，可单独看用量。

2OpenCode Zen / Go API Key（可多个）

登录 opencode.ai → 账户 → API keys 复制（Go / Zen 订阅都是这个入口）。Go 套餐走 /zen/go 端点、模型目录 26 个，应用时自动识别；每个 key 一个渠道，模型名带 oc/ 前缀。

3Command Code 密钥（可多个，自动写入适配器做负载均衡）

在 https://commandcode.ai 设置页获取（形如 user_xxx）。多个 key 会一起写入 cc-adapter 配置热生效。

4路由策略 —— 按模型设置渠道顺序

每条策略 = 一个专用令牌：模型列表 + 渠道顺序（组名，逗号分隔，越靠前越先试）。请求该模型时按此顺序尝试，失败自动切换下一个；顺序可直接在 new-api 令牌编辑里改（auto 分组）。默认两条：luna-adaptive = codex→opencode→cc（给 codex CLI 等 responses 客户端）；luna-chat = opencode→cc（给 chat 客户端，避开官方 chat↔responses 流式转换缺陷）。

5Gemini API key（Google AI Studio）

在 aistudio.google.com 创建 API key（AIza... 开头，多数账号有免费额度）。每个 key 一个渠道，模型名用裸名（如 gemini-3-pro-preview、gemini-2.5-flash）。

统一入口（所有客户端都用这个）

base_url = http://localhost:3000/v1（局域网/远程环境改为主机 IP 或域名，配置模板见工程 clients/ 目录）
✨ 自适应模型 gpt-5.6-luna：OpenCode / Command Code 共用这一个名字，顺序由渠道优先级控制（默认 OpenCode 2 > CC 1），前者限流/失败自动切换；在 new-api 渠道编辑里直接改优先级即可调整顺序。Codex 因官方镜像的 chat↔responses 流式转换缺陷，走前缀名 codex/gpt-5.6-luna（供 codex CLI 等 responses 客户端）
